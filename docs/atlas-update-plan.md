# 欧洲史地图持续补齐计划

本计划响应2026年11月5日用户要求：集中更新，并从此每天北京时间09:00在原对话继续，直到规划节点完成。既有网站和GitHub持续同步，不新建独立地图。

## 有限范围与完成定义

V1的目标清单是：现有历史节点、条约/王位专题、城市焦点年、现有疆界参考年代，加上ledger的计划年份；再审核顾衡260讲中的地理线索，将发现的新关键年纳入清单。不是声称能够枚举欧洲史的一切事实，也不把每个整数年份都虚构成已知实控图。

一讲已关联、一座城市新增单年记录、一块阅读包络重复用于多个年代，都只能作为候选证据，不能自动记为完成。对无独立地理信息的章节，必须读过并写明理由后才能记为不适用。

一个节点达到完成条件需要六类审核：政治实体与称号/时点；政权组成和空间位置；居民身份与语言的独立证据；相关事件及战役地点；疆界资料出处、适用年代、争议及精度；初学者能否完成“在哪里、谁治理、由什么组成、发生什么、和今天哪里对应”的操作。审核可以明确表达无法复原的精度，但不能把未核验的包络称作精确疆界。

未满足条件记为partial或pending。只有所有目标节点与全部章节都已审核，且最终遗漏、来源与交互审计通过，才能报告全部完成并停用每日更新；不得仅因年份都有按钮或计数增长而停止。

## 检查点与脚本

- `docs/atlas-review-ledger.json`：人工审核记录、计划年份和下一批队列，必须写证据与仍缺什么。
- `npm run audit:atlas`：扫描真实数据，区分单年、跨年、政治地域和参考快照；验证页码、地点与来源连接；生成可续跑清单，不自动批准人工审核。
- `docs/atlas-node-progress.json`：提交到GitHub的详细结果；`artifacts/europe-atlas/update-progress.json`为本地镜像。
- `src/europe/atlas-progress-summary.json`：站点资料面板的简明事实，不计算误导性的“全史完成百分比”。

每次开始先看Git状态和最新检查点，已有未完成工作就接着做，避免两个运行同时改同一份数据。遇到权限或额度限制，保留已核验数据与具体后续步骤，不把发布失败写成上线成功。不要自动购买额度或消耗额度重置。

## 每次更新流程

1. 审核最高优先级缺口，按顾衡课程页码找到地理线索，补读独立文书、学术和官方来源。
2. 在同一数据框架补政权、组成地域、城市、居民/语言与事件；分清事前事后、王号帝号、共同君主与实际控制。
3. 更新人工审核记录，运行覆盖审计、适量测试、几何检查、构建和可用的浏览器验收。
4. 将同一源码提交推送GitHub，用Sites现行技能打包保存并部署；必须取得部署成功且线上资源与本地一致。
5. 记录实际发布版本、提交、所增内容、剩余缺口和下一批起点。成功更新或需用户处理的阻碍再报告；状态未变时不重复刷屏。
